# v16.40.4 — Installed iPhone viewport

The supplied iPhone screenshot shows a blurred performance caption below the
status area and an unused strip below the bottom toolbar. The earlier desktop
checks did not exercise the installed iOS viewport or its compositor effects.

Changes:

- Replace the fixed, inset-based app bounds with an explicit viewport-height
  document and a full-height flex shell.
- Use dynamic viewport height normally. Only installed iOS apps with a nonzero
  top safe inset select `100vh`, avoiding the known reduced installed viewport.
  When the OS already excludes its status bar (zero top inset), retain `100dvh`.
- Apply top safe-area spacing once, at the app shell. Keep bottom safe spacing
  on the bottom toolbar and the separate keyboard-dialog layout unchanged.
- In installed portrait iOS apps, reserve an opaque 16px status-edge strip;
  meaningful text starts below it. This is a compatibility mitigation for the
  iOS status blur, not a claim that CSS can disable the native compositor effect.
- Match document, header, and manifest background colours.

Sources inspected:

- https://bugs.webkit.org/show_bug.cgi?id=254868
- https://bugs.webkit.org/show_bug.cgi?id=316008
- https://webkit.org/blog/7929/designing-websites-for-iphone-x/
- Author's iOS 27 edge-strip example:
  https://github.com/hunterirving/events/blob/20141c8b809e4f4a6b976073a8c320a34efb0c86/resources/styles.css

Validation: automated viewport selection tests cover browser/installed modes,
status-overlay/reserved-status layouts, delayed insets, rotation, and keyboard
resize. Existing keyboard and member-navigation tests remain applicable.

Limit: the available browser is desktop Chromium. It cannot reproduce the native
iOS 27 status-bar compositor. A real installed-iPhone visual check remains
unavailable here; do not represent desktop screenshots as iPhone verification.
